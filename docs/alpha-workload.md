| **合计** | | | **18.5** | **100%** |

### 分工原则

- **按交付物分，不按代码文件分**：每项任务有唯一负责人，出问题找得到人。
- **交叉评审**：S1 的地址验证由测试角色复核，S7 的文档由部署角色对照代码核验，
  避免「自己写自己验」。
- **角色不固化**：测试角色在 S7 期间复核 README 中的命令；前端角色在 S2 期间参与
  云端界面的可用性走查。
- **接口约定双签**：S10 产出的 `docs/prototype-api.md` 由后端角色主笔、前端角色确认，
  两人都认可才算完成——这样 Beta 接后端时不会出现「页面要的字段接口里没有」。

## 5. 填写说明

1. 「成员」一列填姓名或昵称，顺序与第 2 节保持一致。
2. 若实际投入与预估偏差超过 20%，直接改「人天」并重算占比，**不要改预估原文**——
   答辩时被问到「为什么估 2 天做了 4 天」比「数字对不上」好回答得多。
3. 占比保留一位小数，合计必须为 100%；精确值相加为 99.96%，按四舍五入把中间一项补到 35.2% 凑满 100%，答辩被问到时照此解释即可。
4. 三人都是团队成员，没有外援。如果实际投入偏差大，优先调整同一角色内任务的负责人，
   而不是新增行。
