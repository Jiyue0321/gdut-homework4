### 分工原则

- **按交付物分，不按代码文件分**：每项任务有唯一负责人，出问题找得到人。
- **交叉评审**：S1 的地址验证由测试角色复核，S7 的文档由部署角色对照代码核验，
  避免「自己写自己验」。
- **角色不固化**：文档角色在 S1 期间参与云端联调，测试角色在 S7 期间复核 README 中的命令。
- **原型独立成线**：S9–S11 由原型负责人主责，不与主站代码交叉；只在 S10 接口约定时
  与后端角色对接一次，避免双双返工。

## 5. 填写说明

1. 「成员」一列填姓名或昵称，顺序与第 2 节保持一致。
2. 若实际投入与预估偏差超过 20%，直接改「人天」并重算占比，**不要改预估原文**——
   答辩时被问到「为什么估 2 天做了 4 天」比「数字对不上」好回答得多。
3. 占比保留一位小数，合计必须为 100%。
4. 第 4 行「原型（外援）」是给不做主站代码的成员预留的；如果原型负责人同时也是主站成员，
   合并成一行、把 S9–S11 并进对应角色，占比按工作量重算即可。
