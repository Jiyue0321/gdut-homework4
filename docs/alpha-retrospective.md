### 2.2 已完成的功能

简历 × 岗位缺口雷达、PDF/TXT/MD 导入、三类面试官轮转（HR / 技术 / 压力）、
单轮自适应追问、交叉拷问取中位数、98 题 / 9 行业定制题库、作答意图过滤、
大模型 JSON 容错与截断修复、Markdown + PDF 双格式导出、失败重试兜底。

### 2.3 关键设计决策（冲刺期不推翻）

1. **编排模式**：阶段流转、题量、追问次数、评分聚合由确定性代码控制，模型只负责生成内容。
2. **评分可复现**：模型出维度分，加权 / 裁剪 / 中位数合并在 `mcp_server/rubric.py`。
3. **工具层双实现**：`LocalTools` 与 `MCPTools` 同源，`USE_MCP` 一键切换——这是云端部署的降级保险。
4. **新原型并行展示**：原型作为独立界面挂出，不替换现有 Streamlit 主站；两者共用同一套
   `agent/` 与 `mcp_server/`，只换界面层。这样原型出问题不影响主站验收，主站的设计决策也不被推翻。

## 4. 改进思路

三条原则，贯穿整个冲刺：

1. **先让人看到，再让人看懂。** 上线优先级高于一切新增功能，上线之后再谈架构。
   没有公网地址，后面所有工作的验收价值都要打折。
2. **把「靠自觉」换成「靠机器」。** 测试、覆盖率、部署状态全部交给 CI 和平台看板，
   不再依赖谁记得跑一下。
3. **冻结功能，偿还技术债。** 冲刺期业务代码只做稳定性修复，不接新需求；
   新想法记进 `docs/backlog.md`，留到 Beta。
4. **原型与主站解耦。** 原型作为并行展示的第二界面，先做到「独立可访问、视觉到位」，
   不急着接后端。界面归界面，引擎归引擎，两边互不阻塞。

### 9.3 需要调整计划的判断

1. **G7 应改判为「已优化但未达标」，并同步修改验收口径。**
   要求是「当场验证」，而实测三次均未进入 3 秒，继续把 G7 写成可达目标会在验收当天变成
   明确的失败项。建议改为两条：
   - **G7a**：单题耗时从基线 5–9 秒降至 3.5 秒以内（相对改进，可当场复测）——**已达成**；
   - **G7b**：单题 ≤3 秒 —— **未达成，原因已定位为外部模型响应时间，代码层无压缩空间**。
   不改需求文档 N5 的目标值，只改冲刺目标的表述方式，使「达成」与「未达成」都如实可查。

2. **S3 优先级应提到最前。** 目前 165 个用例只靠本地手动跑，冲刺期还要做 S7 文档对齐和
   S9 原型接入，改动面不小；没有 CI，回归完全依赖自觉。**已于 2026-11-24 提前完成接入**，
   后续所有改动由 Actions 兜底。

3. **S9 是当前最大的单点风险。** 风险表已将其标为「高」概率，11-26 是原定拿到源码的日期，
   若届时尚无 `prototype/`，应按预案降级为「PDF 截图 + 录屏」，并同步下调 G8、
   重算 `alpha-workload.md` 第 2 节的占比（S9 的 2.0 人天退回）。

4. **新增一条经验：云端验收要用可量化判据，不要靠肉眼。**
   V4 前两次实测「看着正常」，但 16 KB / 15 KB 实际是 CID 回退；换成断言
   （PDF 含 `FontFile2` 且 >16 KB）之后，第 3 次 93 KB 才是真通过。
   这类「看起来对 ≠ 实际对」的坑，冲刺后半段所有验收项都应尽量转成可断言的判据。
