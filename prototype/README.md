# 面面俱到 · 模拟面试原型

> 高保真交互原型，对应 Alpha 冲刺任务 **S9「原型入库与部署」**。
> 纯静态页面：`prototype/index.html` 单文件，零依赖、零构建，双击即可打开。

---

## 1. 打开方式

| 方式 | 操作 |
| --- | --- |
| 本地打开 | 双击 `prototype/index.html`，或浏览器地址栏 `file:///.../prototype/index.html` |
| 本地起服务（推荐，避免个别浏览器的 `file://` 限制） | `python -m http.server 8000 --directory prototype`，然后访问 <http://localhost:8000> |
| 在线预览 | 暂无固定地址，见 §4「部署」的三种方案 |
| 深链接 | 支持 URL 参数直达某一页，便于截图与评审：`?view=front\|admin\|rules`、`?step=1\|2\|3`、`?tab=a1\|a2\|a3\|a4`、`?demo=1`（自动填入示例简历） |

## 2. 技术栈

| 项 | 说明 |
| --- | --- |
| HTML / CSS / JS | 原生实现，全部内联在 `index.html` 一个文件里 |
| 外部依赖 | **无**。没有 CDN、没有 npm、没有字体文件，断网也能正常显示 |
| 构建 | **无**。不需要 `npm install` / `npm run build`，文件即产物 |
| 数据 | 页面内 JavaScript 常量（`QUESTIONS`、`BANK`、`SAMPLE_RES`、`SAMPLE_JD`），不请求任何接口 |

> 单文件是刻意的选择：原型只需要「能打开、能点、能截图」。引入构建链会让它多出一层
> 维护成本，却换不来任何评审价值。

## 3. 页面与交互

### 3.1 三块视图

| 视图 | 内容 | 交互 |
| --- | --- | --- |
| **前台应用原型**（`view=front`） | 录入简历与 JD → 三位面试官轮流提问 → 复盘报告，三态页面流程 | 表单联动校验、一键填入示例、逐题作答、自适应追问演示、已答轮次展开评分依据、报告页雷达图与交叉拷问表 |
| **后台管理原型**（`view=admin`） | 数据概览 / 题库管理 / 系统配置 / 运行日志 四页 | 侧边栏切换、题库按行业 × 角色 × 关键词筛选（12 条样例）、配置开关可点、日志演示输出 |
| **交互与规则说明**（`view=rules`） | 页面流转图、R1–R10 交互规则表、原型与真实系统的对应关系 | 只读说明页，答辩时用来对照讲解 |

### 3.2 可以当场演示的规则

| 规则 | 怎么触发 |
| --- | --- |
| 表单校验 | 打开前台只看得到灰色「开始面试」，简历与 JD 都非空后才可点 |
| 回答过短拦截 | 只打几个字提交，提示「回答太短，请补充细节」，进度不动 |
| 自适应追问 | 回答 8–19 字，触发「（追问）」，题号不前进 |
| 系统反馈过滤 | 输入含「报错 / 异常 / API Key」等词且短于 30 字，提示不计入评分 |
| 题库筛选 | 后台 → 题库管理，行业选「互联网后端」、角色选「技术」，只剩 2 条 |
| 配置开关 | 后台 → 系统配置，四个开关可直接点 |

> 交互逻辑是**演示用的简化实现**（如单题得分由回答字数推导），与真实系统的评分链路无关。
> 真实评分规则见 `docs/requirements.md` 与 `docs/prototype-api.md`。

## 4. 部署（当前选择：先不自建托管）

Alpha 期确认的结论是**只入库、不自建托管**，因此：

- 本原型**没有**长期在线地址，答辩演示走本地打开 + 离线截图；
- 冲刺目标 **G8** 中「长期可访问地址」一项按此降级，验收口径改为「仓库内可打开、可演示」；
- 若 Beta 需要在线地址，以下三种方案都不需要改动源码：

| 方案 | 成本 | 说明 |
| --- | --- | --- |
| GitHub Pages | 低 | 仓库为公开仓库。需在 Settings → Pages 把 Source 设为 GitHub Actions，并加一个只复制 `prototype/` 到 `_site` 的工作流；不要用它跑 Python 测试，那是另一条流水线 |
| 静态托管平台 | 低 | Vercel / Netlify / Cloudflare Pages，Root Directory 填 `prototype`，Build Command 留空 |
| 内网 / 本地 | 零 | `python -m http.server 8000 --directory prototype`，答辩现场起一个即可 |

## 5. 演示数据边界（答辩必答项）

原型上所有数字都是**写死的演示数据**，不是系统真实产出。逐项对照见
[`docs/prototype-api.md`](../docs/prototype-api.md) §2–§4，下表是结论摘要：

| 页面 | 数据完备度 | 答辩口径 |
| --- | --- | --- |
| 前台 · 录入页 | 约 85% ✅ | 字段与现有工具一一对应，接后端无阻塞 |
| 前台 · 面试进行页 | 约 70% | 「简历证据高亮」现有代码无对应字段，Alpha 不做 |
| 前台 · 复盘报告页 | 约 90% ✅ | `session.report_data` 基本够用 |
| 后台 · 概览 | 约 10% | 系统无持久化，会话结束即丢，跨会话统计需 V2.2 的 SQLite |
| 后台 · 题库 | 约 65% | 98 题 / 9 行业 / 27·45·26 角色分布为真实数据；缺难度、使用次数、启用状态 |
| 后台 · 配置 | 约 55% | 模型与 Endpoint 真实可读；API Key 绝不回显；Prompt 可读不可改 |
| 后台 · 日志 | 0% | **待 V2.2**，页面只放演示输出，不做假数据接口 |

> 一句话口径：**主站 = 可运行系统，原型 = 下一版界面设计**；两者共用同一套 `agent/` 与
> `mcp_server/`，只换界面层。

### 6.2 录屏（一条 60–90 秒的完整旅程）

1. 录入页点「填入示例简历」「填入示例 JD」→「开始面试」；
2. 第一题故意只打 10 来个字 → 触发「（追问）」→ 补一段长的 → 提交；
3. 连续提交到第 6 题 → 自动进入复盘报告 → 展开「你的优势 / 待改进 / 行动清单」；
4. 切到后台 → 题库管理按行业筛选一次 → 系统配置点两个开关 → 回前台点「再面一次」。

录屏与截图同步存一份离线副本（`docs/` 或 Release 附件），不要只留本地文件——
分享码与临时链接失效是 Alpha 复盘里列明的「高」概率风险。

| 项 | 说明 |
